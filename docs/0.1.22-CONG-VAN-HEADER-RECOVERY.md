# 0.1.22 – Công văn header recovery

## Scope

This release changes only the document-header and Công văn parsing path. Existing
Báo cáo, Thông báo, Tờ trình, and workflow behaviour is retained.

## Invariants

1. The document's own number and symbol must come from the top header crop.
2. A number or symbol cited after `Kính gửi`, `Thực hiện`, or `Căn cứ` can never
   replace the top header.
3. A Công văn abstract is the italic title block immediately below the own
   `Số ...-CV/...` line and ends before the recipient/body block.
4. Stale values already stored on the website are hints only. They cannot replace
   a bounded focused-header result.
5. A one-character OCR prefix such as `S-CV/ĐU` or `V-CV/ĐU` is removed only
   when the remaining code is a known document code. Office suffixes such as
   `CV/UBKTTU` and `CV/BTCTU` are preserved.
6. Low average OCR confidence does not create a review item when all required
   fields are recovered from strong structural boundaries.

## OCR passes

- wide top-header crop;
- centred number/title crop;
- tight handwritten number band;
- PaddleOCR and Vietnamese Tesseract candidates are compared independently;
- Tesseract number-band variants use PSM 7, 6, and 11 with a restricted
  number/symbol character set.

## Regression coverage

The release includes cases representing records 340, 338, 330, 328, 321, 320,
319, 310, 305, 299, 296, 275, 274, 270, 269, and 268. The tests cover body
citation rejection, handwritten digit normalization, symbol-prefix cleanup,
wrong-type correction, abstract body leakage, missing abstract false positives,
and complete multi-line titles.
