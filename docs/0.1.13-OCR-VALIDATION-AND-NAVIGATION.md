# 0.1.13 - OCR validation and navigation race fix

## Problems fixed

1. Correct records were marked `needs_review` because a whole-page OCR ranking
   score was incorrectly used as a hard Vietnamese-abstract validator.
2. A raw OCR confidence such as 0.60 capped the entire parsed document at 0.60,
   even when number, symbol, type heading and separator were all structurally
   identified with high confidence.
3. A clean value already stored on the website was not used to corroborate or
   rescue a weaker raster OCR result.
4. `Page.goto ... interrupted by another navigation` escaped as a permanent
   failure when the previous Complete redirect was still settling.

## New behavior

- Visible OCR corruption is detected using explicit missing-letter patterns,
  not a generic accent-density threshold.
- Strong structural parsing can pass even when the OCR engine's average numeric
  confidence is lower.
- Existing form values are accepted only when syntactically valid and clean.
  They corroborate matching OCR fields and can rescue a degraded OCR abstract.
- A visibly corrupted existing abstract never overwrites a cleaner OCR result.
- Navigation waits for a stable URL/DOM state, catches both ERR_ABORTED and
  interrupted-navigation messages, verifies the exact UpdateDoc ID, and retries
  safely up to three times.
